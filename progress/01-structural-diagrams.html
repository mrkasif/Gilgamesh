Structural Diagrams — System, Data, and Process Architecture

1. System Architecture Overview

The application follows a layered client–server architecture built on the Next.js App Router. The React client talks exclusively to the application's own API routes; API routes mediate between Supabase Authentication, the Prisma-managed PostgreSQL database (hosted on Supabase), and the Google Gemini API.

6. API Route Map

MethodEndpointWhat it does
GET/api/conversationsList the signed-in user's conversations, newest first (with latest message preview).
POST/api/conversationsCreate a new empty conversation ("New chat"); returns the persisted row.
GET/api/conversations/[id]Return one conversation with its full ordered message history.
PATCH/api/conversations/[id]Update a conversation (title).
DELETE/api/conversations/[id]Delete a conversation and (cascade) its messages.
POST/api/conversations/[id]/messagesAppend a single user/assistant message.
DELETE/api/conversations/[id]/messages/[messageId]Remove a message (used by Regenerate).
POST/api/conversations/[id]/chatSave user turn, call Gemini with full history, persist assistant reply; returns both rows + title.
GET/api/sync-userProvision the Prisma User row from the Supabase identity.
